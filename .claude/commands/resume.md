Загрузи и кратко резюмируй текущее состояние проекта Bordik Med. Используй эту приоритетную последовательность чтения, **в этом порядке**, и остановись как только получишь достаточно для ответа на запрос пользователя.

## Приоритеты чтения (граф ↑ → файлы ↓)

1. **`graphify-out/graph.json`** — если существует, прочитай первым. Это структура кода (~280 токенов вместо ~20k от ре-чтения 80 файлов). Получишь карту: какие модули/компоненты есть, как связаны.

2. **`CLAUDE.md`** — продуктовые стандарты, дизайн-система, архитектура, navigation rules.

3. **`docs/UI_GUIDELINES.md`** — UI-паттерны (если файл существует).

4. **Последний session-лог** — `ls docs/sessions/ | sort -r | head -3`. Прочитай свежий лог (не template) — поймёшь что делалось в прошлой сессии и какие открытые задачи остались.

5. **`docs/AUDIT_TODO_2026-05.md`** + **`docs/CONTENT_ROADMAP.md`** + **`docs/BACKLOG.md`** — открытые задачи, P0/P1/P2 приоритеты.

6. **`docs/TASKS_SNAPSHOT_2026-05-06.md`** (или самый свежий снимок) — реестр задач с метриками.

## Финальный отчёт

После чтения дай пользователю краткое резюме (≤200 слов):

- **Что было закрыто в последней сессии** (1-2 строки на коммит)
- **Что в работе / открыто** (топ-3 P0/P1 задачи)
- **На чём остановились** (последний коммит, есть ли uncommitted changes)
- **Готов продолжить с / Готов начать новое**

Не пересказывай весь репо — только actionable summary. Если пользователь сразу даст следующую задачу, переходи к ней без лишних вступлений.
