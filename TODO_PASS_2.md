## 🔴 Приоритет 1: Базовая стилистика (UI kit)

### 1. Consent-экран теста — переработать под общий стиль

**Файл:** `components/course/TestStartConsent.tsx`

**Что не так:**
- Предупреждение «Во время теста запрещено» и «При нарушении» — отдельные белые карточки без чёткой типографики. Заголовки внутри карточек (`ВО ВРЕМЯ ТЕСТА ЗАПРЕЩЕНО`) цветные (красный / оранжевый) — не в нашей нейтральной стилистике.
- Иконка ⚠ возле главного заголовка «Правила прохождения теста» — цветная (оранжевая на жёлтом фоне). Должна быть **нейтральной** (серой).
- Чекбокс-соглашение «Я прочитал правила, согласен…» — кастомный галочный блок, не в стиле `IOSSwitch` / `Checkbox` из профиля. Выглядит чужим.
- Сами карточки-предупреждения визуально слабые. Можно сделать в **стиле формул / callout** (как мы делаем в `info:` markdown инструментов — серая плашка с подписью `ФОРМУЛА` сверху).

**Что сделать:**
1. Поменять цветные подзаголовки (`#B91C1C`, `#B45309`) на нейтральные серые (`#9CA3AF` с uppercase + letter-spacing, как остальные метки в проекте).
2. Иконку ⚠ в шапке перевести в нейтральный градиент (серый фон `#F5F6F8`, иконка `#6B7280`).
3. Карточки «Запрещено» и «При нарушении» — оформить как callout: тонкая левая рамка (2-3 px), фон `#F5F6F8`, подпись сверху моноширинная uppercase (как у ФОРМУЛА-callout в `app/globals.css:516`).
4. Чекбокс-соглашение заменить на единый стиль с остальными чекбоксами в проекте (изучить `IOSSwitch` / `<input type="checkbox">` в profile/ и привести к одной форме).

**Оценка:** 1 час после готового UI kit (пункт 2).

### 2. Полноценный UI kit — зафиксировать всё на будущее

**Цель:** Один файл (и желательно Storybook или MDX-галерея), где прописано всё — чтобы при любом новом компоненте не тратить время на догадки.

**Что включить:**

#### 2.1. Цвета (tokens)
- Все Brand / Neutral / Semantic оттенки: ровно какие hex для `background`, `surface`, `surface-elevated`, `border`, `text-primary/secondary/tertiary/disabled`, `success`, `warning`, `error`, `info`, `accent`.
- Использовать css-переменные в `app/globals.css`, не хардкодить в inline styles.
- Документ вида: «Используй `--color-text-tertiary` для меток полей, `--color-warning` для нарушений теста».

#### 2.2. Типографика
- Шкала: `display / heading-1-5 / body-lg / body / body-sm / caption / mono-caption / mono-small`
- Для каждого — font-family (display=Montserrat, body=Inter, mono=JetBrains), size, weight, line-height, letter-spacing.
- Правила использования: «Heading-3 = карточки инструментов, Body = описания, Caption = метки».

#### 2.3. Spacing
- 8-point grid: `space-1 (4) / 2 (8) / 3 (12) / 4 (16) / 5 (20) / 6 (24) / 8 (32) / 10 (40) / 12 (48) / 16 (64)`.
- Правила: «Padding карточек=`space-5`/`space-6`, gap между элементами=`space-2`/`space-3`, внешние отступы секций=`space-8`».

#### 2.4. Border radius
- `sm (4), md (8), lg (12), xl (16), 2xl (20), 3xl (24), 4xl (32), full`
- Использование: «Инпуты=lg, карточки=xl/2xl, модалки=3xl, тоги=full».

#### 2.5. Тени
- `shadow-sm` (hover hint), `shadow-md` (карточки), `shadow-lg` (поповеры), `shadow-xl` (модалки).

#### 2.6. Кнопки
- 3 варианта: `primary` (чёрная), `secondary` (серая), `ghost` (transparent).
- 3 размера: `sm` (28h), `md` (36h), `lg` (44h).
- Состояния: idle, hover, active, disabled, loading.
- Иконки: 14px в sm, 16px в md, 18px в lg.
- Типография: body-sm / body.

#### 2.7. Инпуты
- Text input, Number input (с quickValues чипами ниже), Select (dropdown), Checkbox, Radio, Switch (IOSSwitch).
- Метка, плейсхолдер, значение, помощь, ошибка — паттерны.
- Высота поля: 44 px (соответствует lg-button).

#### 2.8. Карточки
- Default card (F5F6F8), elevated (белая с shadow-md), outlined (белая + border), interactive (hover shadow-lg).
- Padding inside: `20px 24px` стандарт, `28px 32px` «просторный».

#### 2.9. Callout / предупреждения
- 5 типов: `info` (синий), `warning` (оранжевый), `error` (красный), `success` (зелёный), `neutral` (серый).
- Структура: иконка 32px + заголовок + тело, слева тонкая цветная полоса 3 px.
- Используется в info-markdown (уже есть `ФОРМУЛА`) + consent тестов + модалки.

#### 2.10. Модалки
- Размеры: `sm (400), md (520), lg (720), xl (960)`.
- Bhackdrop: `rgba(15, 23, 42, 0.55)` + `backdropFilter: blur(2px)`.
- Анимация: fade + scale (0.95 → 1), 180 ms.
- Паддинг содержимого: 28-32 px.

#### 2.11. Иконки
- Набор: Lucide (есть в проекте) + кастомные SVG в `components/icons/`.
- Размеры: `14 / 16 / 18 / 20 / 24 / 32`.
- Stroke-width: `1.8` везде.
- Цвет: наследуется `currentColor`.

#### 2.12. Анимации
- Timing: `ease-out` 180 ms для hover, `[0.05, 0.7, 0.1, 1]` 250 ms для появления, `ease-in` 120 ms для исчезновения.
- Framer-motion: стандартный пресет для fadeInUp, scaleIn, slideFromRight.

**Формат:**
- `docs/ui-kit.md` — текстовое описание + код-сниппеты.
- `components/ui/kit/` — реальные переиспользуемые компоненты (Button, Input, Callout, Modal, Select, Checkbox, IOSSwitch).
- Если время — Storybook или статическая демо-страница `/ui-kit-demo` (не публичная, только для разработки).

**Оценка:** 6-8 часов для каталога + 4-6 часов для переиспользуемых компонентов.

## 🟠 Приоритет 2: Навигация и персистентность

**Пример:** `components/tools/ToolView.tsx` → `CalculatorBody`

**Проблема:** Чекбокс «Мужской пол» между `Возраст` и `ИМТ` сливается с соседними числовыми инпутами, можно пропустить глазом.

**Оценка:** 30 мин (изменение в `CalculatorBody`).

### 4. Дубликаты таба «Источник» в инструментах

**Пример:** WHO MEC / CDC U.S. MEC — в TOC видны и «Источники» (множественное, из markdown headers), и «Источник» (наш `referenceTab`).

**Причина:** Фильтр в `buildInfoTabs` проверяет точное совпадение `'источник'`, но в разных runners заголовок пишется по-разному: `Источник`, `Источники`, `ИСТОЧНИК`, `### Источники`.

**Фикс:** Расширить фильтр в `components/tools/ToolView.tsx:122`:
```ts
.filter(t => !/^источник[иа]?$/i.test(t.title.trim()))
```

И пройтись по всем 602 runners скриптом: найти в `info:` строки `^### Источник` и убрать — они дублируются с полем `reference:` в самом runner'е.

**Оценка:** 20 мин + 20 мин скан runners.

### 5. Сохранение фильтров между навигацией

**Проблема:** Выбрал «Кардиология» + «Только готовые», зашёл в инструмент, вернулся — все фильтры сбросились.

**Причина:** `ToolsPage` хранит state локально через `useState`. При unmount — state теряется.

**Решение:**
- Перенести state фильтров в `useAppStore` (Zustand, уже используется в проекте) под ключом `toolsFilters`.
- При unmount — state сохраняется в store, при mount — восстанавливается.
- Дополнительно: сохранить в URL query params (`?q=BMI&cat=1.+Клинические&avail=true`) — тогда работает share-link + back/forward браузера.

**Оценка:** 1 час (Zustand) + 1 час (URL query sync).

---

### 6. Restore scroll position при возврате

**Проблема:** Проскроллил до `parkland`, открыл его, нажал «Назад» — попал в начало списка, надо заново скроллить.

**Решение:**
- Зафиксировать `scrollTop` скролл-контейнера при открытии инструмента (в `onSelect` в `ToolsPage`).
- При возврате (через `onBack`) — восстановить `scrollParent.scrollTop = savedPosition` после mount списка.
- Virtuoso поддерживает `restoreStateFrom` — это правильный путь для виртуализированного списка.
- Сохранить в том же store что и фильтры (п.5): `toolsScrollPosition`.

**Оценка:** 1 час (интеграция Virtuoso restoreStateFrom).

### 7. Избранное (Favorites)

**Цель:** Пользователь может добавить инструмент в «избранные» — быстрый доступ с главной / профиля.

**Задачи:**
- Иконка-звёздочка на карточке инструмента + внутри `ToolView` (справа от тега тип/раздел).
- Клик → toggle в `useAppStore.favoriteTools: string[]`.
- Персистентность через Zustand `persist` middleware (localStorage).
- Отдельный раздел «Избранное» в каталоге (фильтр или отдельная вкладка).
- Индикация в карточке (заполненная звёздочка vs пустая).

**Оценка:** 2-3 часа.

### 8. Тултипы с подсказками везде

**Пример:** PANSS — возле поля «Позитивная подшкала P» значок ℹ с тултипом «P1-P7: бред, концептуальная дезорганизация…».

**Что сделать:**
- Компонент `<Tooltip>` в UI kit (радиус 12px, max-width 280px, стрелочка к якорю, dark background `#1A1A1A` / white text, fade 150ms).
- Проход по всем runner inputs: если есть `description` или клиническое пояснение — добавить ℹ рядом с лейблом, при hover/tap показывать.
- Для touch-devices — tooltip должен показываться на click, закрываться на click outside.
- Добавить `tooltip?: string` в `ToolInput` типизацию и отрендерить в `InputField`.

**Оценка:** 2 часа (компонент + интеграция) + 2 часа (прописать description в ~150 runners где есть смысл).

## 🟡 Приоритет 3: Фильтры и косметика

### 9. Фильтр «Страны» — сгруппировать по основной стране

**Проблема:** Сейчас показывает `Канада (CATCH)`, `Канада / Международный (QxMD…)`, `Австралия`, `Австралия, Новая Зеландия` — слишком гранулярно. Пользователь фильтрует по «Канаде», не по конкретному подписанию.

**Решение:**
- Извлечь из `countries:` ПЕРВУЮ страну (до скобки или первой разделительной запятой).
- Группировать одинаковые («Канада» и «Канада / Международный» → обе в группу «Канада»).
- Показать список как: `🇷🇺 Россия (23)` / `🇺🇸 США (87)` / `🇬🇧 Великобритания (12)` / `🌐 Международный (280)`.
- Если инструмент имеет несколько стран — попадает в каждую из соответствующих групп.

**Файлы:** `components/tools/ToolsPage.tsx` (логика фильтра стран) + `lib/country-utils.ts` (новый утиль).

**Оценка:** 2 часа (парсинг + группировка + UI).
